# Q5 - Synchronisation

Build with `gcc -std=c11 -Wall -Wextra -Wpedantic -pthread file.c -o program`. `bounded_buffer_todo.c` completes the supplied semaphore/mutex program. `bounded_buffer.c` checks exact-once delivery with 1/1 and 4/4 producers/consumers, repeats the 4/4 test 100 times, then benchmarks global, per-train and per-coach lock scopes. `sync_primitives_bench.c` compares mutex, atomic increment and spin lock with 1, 4 and 16 threads, recording wall and process CPU time. Results: `../evidence/task05-buffer.txt`, `../evidence/task05-todo.txt` and `../evidence/task05-primitives.csv`.

Removing the mutex from a 4-producer/4-consumer bounded buffer leaves concurrent updates to the shared `in`/`out` indices and buffer slots unprotected. The `empty` and `full` semaphores count capacity/items but do not make those multi-step updates mutually exclusive; ordinary C data races have undefined behavior and cannot guarantee exactly-once consumption. This explains why the mutex remains in the tested multi-worker version.
